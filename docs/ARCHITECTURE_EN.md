# Architecture

## Data and control flow

```text
User / Agent
    │ JSON command
    ▼
live/live_cli.py
    │ Write a temporary file, then atomically rename it to request.json
    ▼
live/projects/<session>/requests/
    │ RP8 host polls for requests
    ▼
RP8Live.next.exe WPF Dispatcher
    │ Version-pinned native editing calls
    ▼
Axure RP 8 pages, widgets, interactions, and saver
```

## Components

### Launcher

RP8LiveLauncher.cs is compiled by live/build.cmd into 打开独立RP8.exe. The launcher accepts an .rp path, copies the project to a unique local working directory, and starts the dedicated RP8 host. If a dedicated host is already active, it reuses that instance without activating its window or switching files.

### Dedicated host and version gate

RP8Live.cs runs as a separate x86 WPF process and loads the original Axure RP 8 installation. At startup, it verifies the SHA-256 hashes of the Axure executable and related DLLs; it refuses to enter the editing workflow if they do not match. The host works through native RP8 client objects and editor services, and limits changes to the copy assigned by the launcher.

Commands execute on the WPF Dispatcher, with focus protection that keeps the RP8 canvas visible while blocking attempts by the host to take foreground focus. The program does not simulate mouse, keyboard, or clipboard input.

### JSON command client

live/live_cli.py reads the active session path from live/session.json, writes a JSON request to a temporary file, and atomically renames it into the request directory. The host polls that directory, executes the request on the UI Dispatcher, and writes a response. Each session's runtime state and request artifacts stay in the local working directory.

### Native editing adapter

- RP8Live.cs: page navigation, widget reads and writes, style/interaction routing, saving, capture, and HTML export.
- RP8Styling.cs: style allowlist, gradient/solid fills, shadows, and editable vector paths.
- RP8Interactions.cs: creation and reading of native events, cases, conditions, and actions.
- RP8LiveLauncher.cs: working-copy and host lifecycle.

The code uses .NET reflection to access RP8 internal assemblies and editing transactions. This is not an official Axure SDK and does not claim compatibility with other versions.

## Saving and acceptance

The save command calls RP8's native file-save entry point. HTML previews are generated by Axure's own generator. Acceptance should check separately that the native file reopens, the expected pages/widgets exist, and interactions behave as expected in a browser. Passing one check does not imply that the others passed.

## Reuse boundary

live/ contains the generic adapter. It does not include user pages, brand styles, project files, screenshots, session logs, or product-specific build scripts. Page design requirements should be supplied separately to the agent or by the user.
