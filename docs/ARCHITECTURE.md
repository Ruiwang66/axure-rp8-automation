# 架构说明

## 数据与控制流

```text
用户 / Agent
    │ JSON 命令
    ▼
live/live_cli.py
    │ 写入临时文件，再原子改名为 request.json
    ▼
当前会话的 live/projects/<id>/requests/
    │ RP8 宿主轮询请求
    ▼
RP8Live.next.exe 的 WPF Dispatcher
    │ 版本绑定的原生编辑调用
    ▼
Axure RP 8 页面、元件、交互和保存器
```

## 组件

### 启动器

`RP8LiveLauncher.cs` 由 `live/build.cmd` 编译为 `打开独立RP8.exe`。启动器接收一个 `.rp` 路径，把工程复制到唯一的本机工作目录，再启动专用 RP8 宿主。存在活动专用宿主时，它会复用现有实例，不会激活窗口或切换文件。

### 专用宿主和版本门禁

`RP8Live.cs` 作为独立 x86 WPF 进程加载安装目录中的原版 Axure RP 8。启动时逐个校验 Axure EXE 与相关 DLL 的 SHA-256；版本不匹配则拒绝进入编辑流程。宿主通过原生 RP8 客户端对象和编辑器完成工作，并把所有变更限定到启动器分配的副本。

WPF Dispatcher 上的命令检查和焦点保护使 RP8 画布保持实时可见，同时拦截宿主主动抢前台焦点的请求。程序不模拟鼠标、键盘或剪贴板输入。

### JSON 命令客户端

`live/live_cli.py` 读取 `live/session.json` 的当前会话路径，将 JSON 写到临时文件，再原子改名为请求文件。宿主轮询请求目录，在 UI Dispatcher 上执行命令并写回响应。每个会话的运行状态和请求材料都保存在本机工作目录。

### 原生编辑适配器

- `RP8Live.cs`：页面导航、元件读写、样式/交互路由、保存、截图和 HTML 导出。
- `RP8Styling.cs`：样式白名单、渐变/纯色填充、阴影和可编辑矢量路径。
- `RP8Interactions.cs`：原生事件、用例、条件和动作的创建与读取。
- `RP8LiveLauncher.cs`：工作副本和宿主生命周期。

这些代码使用 .NET 反射访问 RP8 的内部程序集与编辑事务。它不是 Axure 官方 SDK，也不承诺对其他版本兼容。

## 保存和验收

保存命令调用 RP8 原生文件保存入口。HTML 预览由 Axure 自带生成器输出。验收应分别检查原生文件能否重新打开、页面和元件是否存在，以及浏览器中交互是否按预期运行；仅有某一种检查不能代表其他检查也通过。

## 可复用性边界

`live/` 是通用适配器；它不带用户页面、品牌样式、项目工程、截图、会话日志或特定产品的构建脚本。页面设计规格应作为独立输入交给 Agent 或由使用者提供。
